# Security model

No database is used. Sessions carry a random 256-bit ID and CSRF token plus an 8-hour expiry, authenticated with HMAC-SHA-256 using SESSION_SECRET. Cookie contents are signed, not encrypted; they contain no password or storage credential. Cookies remain HttpOnly, SameSite=Strict and Secure in production. All admin pages check the session on the server; all admin API reads require session, writes require session + exact Origin + session CSRF header. Login requires exact Origin. No frontend-only auth or disabled-auth fallback.

Login throttling uses bounded in-memory expiry maps: 10 attempts/address and 100 total per 15-minute fixed window **per process/serverless instance** (successful attempts count too). The instance-wide bucket also counts rejected address attempts. Only Vercel's platform forwarded IP is used on Vercel; other hosts share one local bucket and must review proxy assumptions. Each map holds at most 4096 entries, expired entries are pruned on access, and full maps reject new entries rather than evicting live protections. Updates are synchronous within one JS process, not distributed or durable. Cold starts/restarts reset counters; parallel instances have independent budgets. A platform-level firewall/rate limit can complement this best-effort safeguard without an application database. TLS required; no password/session/token logging.

Logout always clears the browser cookie and records a hashed token denylist entry until expiry in the current instance only. A copied cookie can still replay on another instance or after restart until its signed expiry. Denylists are bounded too; capacity exhaustion reports an error rather than falsely confirming replay protection. This is **not durable or globally effective revocation**. Signed cookies continue to work across instances sharing SESSION_SECRET without session storage. Rotate SESSION_SECRET consistently on all deployments (and retire old instances) to invalidate all old sessions; changing only ADMIN_PASSWORD does not invalidate existing signed sessions.

Schema validation is strict; bounded JSON streaming body, bounded image streams; regex paths avoid traversal. Uploads accept magic-byte JPEG/PNG/WebP only, decode with Sharp pixel limits, reject animation, rotate/resize/re-encode (strip EXIF), store immutable hashed paths. SVG/HTML/GIF/remote URLs are rejected. No remote fetch importer, so no SSRF. Images are not deleted physically when detached (shared/referenced images remain safe); planned garbage collection should require explicit review.

React escapes all plain text. JSON-LD escapes '<'. CSP prevents embedding, objects and arbitrary remote scripts; Next.js inline hydration requires unsafe-inline in this initial build, so this is not a strict nonce CSP. Image sources are restricted to self/data. OpenStreetMap is the only iframe. External links use noopener. Add HSTS at the real HTTPS host; do not apply it to local HTTP.

Password is compared through fixed-length SHA-256 digests with timingSafeEqual; the password secret itself remains server ENV, not persisted in GitHub. No password recovery endpoint. Rotate credentials through hosting secrets; rotate SESSION_SECRET to invalidate all current sessions. Monitor errors and instance-local login rate limits.

Concurrency: browser supplies observed SHA; GitHub PUT with SHA returns 409 on stale edits, no automatic overwriting. Local test mode serializes mutations and atomic renames. All data stored as a single validated envelope. Token scope should be the minimum repository permissions. Tests cover signed-cookie tampering/expiry, local throttle windows and bounds, local-only replay denial and Origin fail-closed behavior. Production GitHub runtime reads/writes and platform security still need verification before launch; no database integration is required.
